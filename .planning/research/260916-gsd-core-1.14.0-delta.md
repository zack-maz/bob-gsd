### 2.4 What `hostIntegration.dispatch` means for Bob

The axis is consumed at three places:
`NEW: gsd-core/bin/lib/host-integration.cjs:534-580` (`resolveDispatchType`),
`gsd-tools.cjs:2629` (`query resolve-dispatch-type`), and the
`query dispatch-isolation` / `dispatch-capacity` / `dispatch-should-flatten` verbs.
Semantics for Bob, given Bob 2.x has `spawn_subagent` (isolated context, parallel
fan-out within one turn, no nesting) and Bob 1.0.x has no subagent tool at all:

| Sub-field | Bob 2.x value | Meaning / consequence |
|---|---|---|
| `namedDispatch` | `true` | GSD role names (`gsd-planner`, `gsd-executor`) dispatch directly. If it were `false`, `resolve-dispatch-type` would map every role onto a built-in (the kimi-code path, `NEW: gsd-core/references/runtime-aware-dispatch.md:7-11`) — Bob does not need that. |
| `nested` | `false` | No subagent-inside-subagent. Combined with `maxDepth: 1` this makes `shouldFlattenDispatch` (#853, #2939) flatten any second-level fan-out into the parent turn — which is exactly right for Bob: an orchestrator skill may spawn workers, a worker may not. |
| `maxDepth` | `1` | Honoured as the depth budget by `shouldFlattenDispatch` (#2939, v1.10.0). |
| `background` | `true` | The parent may continue while subagents run — i.e. real parallel fan-out in one turn. |
| `backgroundDispatch` | `false` | Bob has no documented "fire and forget, collect later across turns" primitive (distinct from `background`; see `NEW: …/capability-validator.cjs:1616-1626`). |
| `subagentToolkit` | `'full'` | Spawned subagents get the full tool set (`{full, read-only, built-in-only}`). Set `'read-only'` only if Bob restricts child tools. |
| `isolation` | `'none'` | Bob has no *worktree* isolation primitive (`{harness-worktree, orchestrator-worktree, none}` — this axis is about git worktrees, **not** context isolation). Consequence: `execute-phase` fails **closed** and refuses to dispatch a parallel wave unless the project sets `workflow.use_worktrees=false` (`NEW: gsd-core/workflows/execute-phase/steps/executor-isolation-dispatch.md`, the `FATAL: runtime '$RUNTIME' declares no executor-isolation primitive` arm). **This is the single biggest behavioural gotcha of the bump** — see Risks. Declaring `'orchestrator-worktree'` instead would require a valid `runtime.orchestratorExec` (headless `bob` argv), which is plausible with BobShell but must be spike-verified before it is declared. |
| `maxConcurrency` | `'undocumented'` | Degrades to the safe floor of 1 with a warning (`query dispatch-capacity`, #3673). Set a real integer once Bob's fan-out width is documented. |

For **Bob 1.0.x** (no subagent tool) the honest declaration is
`namedDispatch: false, nested: false, maxDepth: 0, background: false,
backgroundDispatch: false, subagentToolkit: 'built-in-only', isolation: 'none'` —
which routes GSD onto the "agent-skills fallback for non-dispatchable runtimes"
path (#2505 Phase 3, v1.9.0; `NEW: gsd-core/references/agent-skills-bootstrap.md`).
A single descriptor cannot express both Bob majors; the adapter must pick the
conservative one or gate on a detected Bob version (`host-runtime-detection.cjs`
is new in 1.14.0 and may help).

### 5.2 Why the floor was raised (upstream evidence)

- `upstream-gsd-core/CHANGELOG.md:571` — "**GSD now requires Node 24 or newer** — the
  `engines.node` floor moves from 22 to 24, and the Node 22 test lane is retired.
  Node 22 entered Maintenance LTS and this project tracks the Active LTS line; the
  change is what lets regex escaping delegate to the built-in `RegExp.escape`…" (#3416)

- `…/3212-…md:177` — "**Risk:** the Node 24 floor strands consumers on Node 22 until

  the fallback."
- **Then the shim was shipped anyway:** `CHANGELOG.md:672` — "**The build no longer

  `RegExp.escape` is absent** (#3498) … Behavior on Node 24+ is unchanged; match
  behavior below Node 24 is verified equivalent by regression tests that neuter
  `RegExp.escape` in a child process." (#3499, shipped in v1.11.0)

  CI runs Node 24 only, so Node 22 is **untested**, not broken.

### 5.3 Conclusion

**The vendored `gsd-core/bin` payload will run on Node 22.15.** The `>=24.0.0` floor
is an LTS-tracking *policy* decision whose one concrete technical driver
(`RegExp.escape`) was explicitly re-shimmed by #3499 before 1.14.0 shipped. No
Node-24-only API is reachable in the vendored tree.

Caveats for gsd-bob:
1. This is an **untested configuration** upstream — the Node 22 CI lane is retired.
2. Bob Shell itself requires Node `>=22.15.0`, so the *union* floor is `>=22.15.0`.
3. `npm` will warn (not fail) on `engines` mismatch if the vendored payload's
   version is ever surfaced through a real `package.json` — gsd-bob synthesizes a
   minimal one with no `engines`, so no warning today.
4. **Recommendation:** keep gsd-bob's own `engines.node` at `>=22.15.0`, and add a
   CI lane on Node 22.15 that runs the staged-shim test. Document the divergence
   from upstream `>=24` in `UPSTREAM.md`, since a maintainer will ask.

3. **Agent-skills fallback for non-dispatchable runtimes** (#2505 Phase 3, v1.9.0)

   (`global:<plugin>:<skill>`) are **Claude-only** and skipped with a warning

## Risks for the re-vendor — ranked by severity

1. **CRITICAL — `dispatch.isolation: 'none'` hard-blocks `/gsd-execute-phase`.**
   `NEW: gsd-core/workflows/execute-phase/steps/executor-isolation-dispatch.md` now
   `exit 1`s with `FATAL: runtime '$RUNTIME' declares no executor-isolation
   primitive (dispatch.isolation=none) — executors would run unisolated against the
   main checkout. Set workflow.use_worktrees=false.` unless the project config
   disables worktrees. Bob's `spawn_subagent` gives **context** isolation, not a git
   worktree, so it cannot satisfy this gate. The core value ("run the full GSD
   planning loop natively") breaks on the first `execute-phase` unless gsd-bob ships
   `workflow.use_worktrees=false` as an installed default (or writes it into
   `.planning/config.json` on install) — or declares
   `isolation: 'orchestrator-worktree'` with a verified `runtime.orchestratorExec`
   for headless BobShell. **Decide this before re-vendoring; it is a product
   decision, not a patch.** Gates at `references/dispatch-isolation-gate.md` and 10
   other workflow sites.

2. **CRITICAL — patch step 4b throws on the 1.14.0 tree.**
   `convertClaudeCommandToCursorCommand,` no longer exists anywhere in
   `runtime-artifact-conversion.cjs`, so `apply-bob-patches.cjs` aborts with
   `[4b] converter: export anchor … not found` and leaves the payload in a
   half-patched state (4a applied, exports missing → `stage.cjs:274-277` destructures
   `undefined` and the convertible loop crashes). One-line fix (§3.2), but it is a
   hard stop, and the half-applied intermediate state defeats the idempotency
   contract. **Add a "verify all 8 deltas applied" post-check to the runbook.**

3. **HIGH — the current `"bob"` registry block is schema-invalid for 1.14.0.**
   Missing `localConfigDir` (required since v1.7.0 — `getDirName` derives from it, so
   local-scope dir resolution has no descriptor value), missing `hostIntegration`
   (required; every `dispatch-*` / `resolve-dispatch-type` query and
   `negotiateHostCapabilities` read it and will fail closed or throw), and
   `hookEvents: "none"` is outside `VALID_HOOK_EVENTS = {claude, gemini}` and always
   was. The frozen registry isn't validated at load, so this fails **late and
   silently** rather than at install — the worst failure shape. Fix per §2.3.

   gsd-bob's `engines.node` to `>=22.15.0`, add a Node 22.15 CI lane running the
   staged-shim test, and re-run the Node-24-API grep on every bump. Expect this to
   break eventually.
